# Архитектура Go-сканера

Документ описывает быстрый сканер коллекции, написанный на Go, и его
нативный приёмник в БД (`scansvc`).

## Цели

- Ускорить сканирование больших коллекций за счёт параллельного обхода и парсинга.
- Полный дата-паритет: книги, авторы, серии, жанры.
- Писать напрямую в БД Go-ядра — без Python.

## Поток данных

```
cmd/eopds (serve)  ──► admin.handleScanRun  ──► scansvc.Run(ctx, store, Options)
                                                      │
                                       internal/walk  — параллельный обход (worker pool)
                                       internal/fb2   — парсер FB2 (encoding/xml)
                                       internal/charset — windows-1251 → UTF-8
                                                      │  эмитит meta.Record:
                                                      │   {"kind":"book", ...}
                                                      │   {"kind":"stats", ...}
                                                      ▼
                  store.ImportBooks (пачка ~500 книг: одна транзакция + per-book SAVEPOINT)
```

`eopds-scanner` (cmd/eopds-scanner) — автономный бинарник того же сканера,
печатающий записи в stdout (JSON Lines). Используется для отладки/внешних
интеграций; в штатной работе админка вызывает `scansvc` напрямую, в процессе.

## Протокол записей сканера (`meta.Record`)

Поля книги: `rel_path`, `filename`, `format`, `size`, `title`, `lang`,
`docdate`, `annotation`, `authors[]`, `genres[]`, `series{title,index}`,
`book_path`. Для zip-архива: `archive`, `member`, `catalog_type`.

## Ключевые оптимизации

1. **Ранний выход после `</description>`** — метаданные FB2 находятся только
   в `<description>`; парсер прекращает чтение сразу после него, не читая
   тело книги и base64-картинки.
2. **Потоковый charset** — windows-1251 транслируется в UTF-8 инкрементально,
   без загрузки всего файла в память (`internal/charset`).
3. **Пул воркеров** — параллельный обход и парсинг (`Workers`, 0 = NumCPU).
4. **Пакетная запись** — книги пишутся пачками (одна транзакция + SAVEPOINT,
   кэш справочников), см. раздел ниже.
5. **Инкрементальный скан** — неизменившиеся файлы/архивы пропускаются по
   `size`+`mtime` (таблица `scan_files`), см. раздел ниже.

## Дата-паритет

- Авторы: `first-name` + `last-name`, затем фамилия переносится в начало.
- Серия: **только первая** `<sequence>` из `title-info`.
- docdate: `document-info/date/@value`, иначе текст.
- Кодировки: windows-1251 декодируется потоково.

## Приёмник `internal/scansvc`

`scansvc.Run(ctx, store, Options{Roots, Zip, Exts, BatchSize, ...})` подключает
`walk` к `io.Pipe`, построчно читает поток `meta.Record`, накапливает книги в
буфер и пишет их **пачками** через `store.ImportBooks`.

Как устроено:

- **Пакетная запись.** Книги собираются в буфер (по умолчанию `BatchSize=500`)
  и пишутся одной транзакцией на пачку — `store.ImportBooks(ctx, books)`.
  Внутри пачки каждая книга обёрнута в `SAVEPOINT`: ошибка одной книги
  откатывает только её, остальные сохраняются. Ошибки книг учитываются в
  `ImportErrors` и не прерывают пачку.
- **Кэши справочников.** В пределах пачки кэшируются `authors`/`series`/
  `genres`/`catalogs` (по уникальному ключу), поэтому повторные SELECT для
  уже виденных авторов/серий/жанров/каталогов не выполняются — критично для
  коллекций с тысячами повторов.
- Запись книги: `books` (upsert по `path+filename`), `catalogs` (по `path`),
  `authors`/`series`/`genres` (по уникальным ключам) и связи
  `book_authors`/`book_series`/`book_genres`.
- Связи вставляются через `INSERT ... ON CONFLICT DO NOTHING`: в PostgreSQL
  нельзя «проглотить» ошибку уникальности внутри транзакции (она станет aborted),
  поэтому конфликт разрешает сам SQL.
- Импорт **идемпотентен**: повторное сканирование обновляет существующие книги
  и не создаёт дублей (тесты `TestImportBookIdempotent`, `TestImportBooksBatch`).
- Плейсхолдеры `%s` → `$1..`/`?` подставляются `bind()`.
- `scansvc.Result` считает `BooksFound` (найдено), `BooksCreated` (новые),
  `BooksUpdated` (обновлённые), `BooksParsed` (успешно импортировано),
  `ImportErrors` (ошибки парсинга/импорта) и `Skipped` (пропущено как
  неизменившиеся — инкрементальный скан).
- `Options.OnError(relpath, filename, errmsg)` вызывается по каждому
  нечитаемому/битому файлу или архиву. Админка превращает их в сообщения
  системы (`scan.error`, полный путь вида `архив.zip/файл`) — см.
  [system-events.md](system-events.md).
- **Почему быстро:** одна транзакция на пачку вместо транзакции на книгу +
  кэш справочников. Замер на коллекции из 6210 книг: первичный скан
  ~11 с (было ~58 с), повторный — ~8 с (≈5–7x).

`store.ImportBook` (одна книга) остаётся для точечных вызовов (тесты, API) и
внутренне использует ту же `importBookCore`-логику.

Веб-интерфейс:

- Каталоги для сканирования задаются в `/settings` (ключ `scan.paths`, JSON-массив).
  Сканирование **рекурсивное**: обходятся все подкаталоги указанного пути.
- `POST /scan/run` (только admin/root) запускает сканирование в **фоновой
  горутине** с собственным `context.Background()` и сразу делает `303` на `/scan`.
  Скан **не привязан к HTTP-запросу**: браузер можно закрыть, процесс продолжится.
  Это критично для больших коллекций (скан может идти часы).
- От одновременного запуска защищает `scanState` (атомарный `begin()` — только
  одна задача за раз; повторный `POST /scan/run` игнорируется).
- `GET /scan/status` отдаёт JSON-снимок прогресса (`running`, `found`, `created`,
  `updated`, `errors`, `started_at`, `finished_at`). Страница `/scan` опрашивает
  его каждые 2с и показывает плашку с живым счётчиком; после завершения —
  перерисовывается с итогом.
- Прогресс передаётся из сканера через колбэк `Options.OnProgress(Progress)`
  (вызывается после каждой книги).
- Счётчики дашборда (`store.Stats()`) сразу отражают число книг/авторов/серий.
- Очистка библиотеки (кнопка в `/settings`) удаляет книги и связанные сущности
  (`store.ClearLibrary`), не трогая пользователей и настройки.

> Примечание. Ранее скан выполнялся синхронно внутри HTTP-запроса: при обрыве
> соединения/таймауте браузера `r.Context()` отменялся, импорт прерывался
> посреди архива (`context canceled`) и в статистику попадали ложные «ошибки».
> Раннер `scansvc` теперь трактует отмену контекста как штатную остановку
> (не ошибку импорта) и не выполняет `PruneCatalogs` при прерывании.

## Инкрементальный скан

Повторное сканирование не перечитывает файлы, которые не изменились.

- **Отпечаток файла.** Для каждого источника (`size`, `mtime` в наносекундах)
  хранится запись в таблице `scan_files` (`path` — относительный путь):
  отдельная книга → `rel_dir/filename`; ZIP-архив → путь к архиву.
- **Проверка в `walk`.** Перед парсингом `walk` сравнивает `size`+`mtime`
  файла с отпечатком (`walk.Options.Known`). Совпало → файл пропускается
  (счётчик `skipped`), не читается с диска и не парсится.
- **ZIP целиком.** Для архива фиксируется отпечаток самого `.zip`
  (`KindArchiveEnd` с `size`/`mtime`). Если архив не менялся — пропускается
  весь zip без распаковки; изменился — книги внутри перечитываются.
- **Когда пишется отпечаток.** `scansvc` сохраняет отпечатки **после
  успешного импорта пачки** (`store.SaveScanFiles`). Битая/непрочитанная
  книга не оставляет отпечатка и будет перечитана в следующий раз.
- **Полный перескан.** `Options.FullRescan` (в UI — чекбокс «Полный скан»,
  API — `POST /scan/run` с `full=1`) игнорирует отпечатки и перечитывает всё.
- **Очистка библиотеки** удаляет и `scan_files` (иначе новый скан считал бы
  файлы прочитанными).

Эффект на коллекции 6210 книг: первичный скан наполняет `scan_files`
(8 источников: 5 zip + 3 файла); повторный скан без изменений —
`skipped=8`, `found=0`, **< 1 с**.

> `mtime` зависит от файловой системы и копирования. Если файлы перенесены/
> восстановлены с сохранением содержимого, но новый `mtime`, они будут
> перечитаны (это безопасно, просто медленнее). При необходимости —
> `full=1`.

## Статистика сканирования (дашборд)

- `scansvc.Result` содержит `StartedAt` и `Elapsed` (общая длительность обхода+импорта).
- После каждого запуска итог сохраняется в настройку `scan.last` (JSON `ScanSummary`):
  `started_at` (RFC3339, UTC), `elapsed_ms`, `found`, `created`, `updated`, `import_errors`.
- На дашборде (`/`) отображается блок «Последнее сканирование»:
  **Начало** (дата/время старта), **Продолжительность** (человекочитаемо: ч/мин/с)
  и краткая сводка `найдено · создано · обновлено [· ошибок]`.
- На `/scan` строка результата также содержит начало и длительность.

Время старта хранится в UTC; при отображении приводится к локальной зоне процесса.

## Коллекция из ZIP (пример развёртывания)

`docker-compose.go.yml` монтирует каталог коллекции read-only во внутренний путь
контейнера:

```yaml
volumes:
  - /run/media/ahtoh/SSD2/e-book:/books:ro
```

Сканер обходит `/books` рекурсивно и распаковывает ZIP-архивы с FB2 (`Zip: true`).
Путь добавляется в разделе «Каталоги сканирования» (`/settings`).
