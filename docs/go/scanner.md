# Архитектура Go-сканера

Документ описывает быстрый сканер коллекции, написанный на Go, и его
нативный приёмник в БД (`scansvc`).

## Цели

- Ускорить сканирование больших коллекций за счёт параллельного обхода и парсинга.
- Полный дата-паритет: книги, авторы, серии, жанры.
- Писать напрямую в БД Go-ядра — без Python.

## Поток данных

```
cmd/eopds (serve)  ──► admin.handleScanRun  ──► scansvc.Run(ctx, store, Options)
                                                      │
                                       internal/walk  — параллельный обход (worker pool)
                                       internal/fb2   — парсер FB2 (encoding/xml)
                                       internal/charset — windows-1251 → UTF-8
                                                      │  эмитит meta.Record:
                                                      │   {"kind":"book", ...}
                                                      │   {"kind":"stats", ...}
                                                      ▼
                          store.ImportBook (транзакция на книгу, upsert по path+filename)
```

`eopds-scanner` (cmd/eopds-scanner) — автономный бинарник того же сканера,
печатающий записи в stdout (JSON Lines). Используется для отладки/внешних
интеграций; в штатной работе админка вызывает `scansvc` напрямую, в процессе.

## Протокол записей сканера (`meta.Record`)

Поля книги: `rel_path`, `filename`, `format`, `size`, `title`, `lang`,
`docdate`, `annotation`, `authors[]`, `genres[]`, `series{title,index}`,
`book_path`. Для zip-архива: `archive`, `member`, `catalog_type`.

## Ключевые оптимизации

1. **Ранний выход после `</description>`** — метаданные FB2 находятся только
   в `<description>`; парсер прекращает чтение сразу после него, не читая
   тело книги и base64-картинки.
2. **Потоковый charset** — windows-1251 транслируется в UTF-8 инкрементально,
   без загрузки всего файла в память (`internal/charset`).
3. **Пул воркеров** — параллельный обход и парсинг (`Workers`, 0 = NumCPU).

## Дата-паритет

- Авторы: `first-name` + `last-name`, затем фамилия переносится в начало.
- Серия: **только первая** `<sequence>` из `title-info`.
- docdate: `document-info/date/@value`, иначе текст.
- Кодировки: windows-1251 декодируется потоково.

## Приёмник `internal/scansvc`

`scansvc.Run(ctx, store, Options{Roots, Zip, Exts, ...})` подключает `walk`
к `io.Pipe`, построчно читает поток `meta.Record` и пишет книги через
`store.ImportBook`.

Как устроено:

- Запись одной книги — одна транзакция: `books` (upsert по `path+filename`),
  `catalogs` (по `path`), `authors`/`series`/`genres` (по уникальным ключам)
  и связи `book_authors`/`book_series`/`book_genres`.
- Связи вставляются через `INSERT ... ON CONFLICT DO NOTHING`: в PostgreSQL
  нельзя «проглотить» ошибку уникальности внутри транзакции (она станет aborted),
  поэтому конфликт разрешает сам SQL.
- Импорт **идемпотентен**: повторное сканирование обновляет существующие книги
  и не создаёт дублей (тест `TestImportBookIdempotent`).
- Плейсхолдеры `%s` → `$1..`/`?` подставляются `bind()`.
- `scansvc.Result` считает `BooksFound` (найдено), `BooksCreated` (новые),
  `BooksUpdated` (обновлённые), `BooksParsed` (успешно импортировано) и
  `ImportErrors` (ошибки импорта).

Веб-интерфейс:

- Каталоги для сканирования задаются в `/settings` (ключ `scan.paths`, JSON-массив).
  Сканирование **рекурсивное**: обходятся все подкаталоги указанного пути.
- `POST /scan/run` (только admin/root, одна задача за раз — `atomic.Bool`)
  сканирует эти каталоги и пишет результат в БД; на `/scan` показывается
  «найдено N (создано X, обновлено Y), импортировано Z, ошибок E».
- Счётчики дашборда (`store.Stats()`) сразу отражают число книг/авторов/серий.
- Очистка библиотеки (кнопка в `/settings`) удаляет книги и связанные сущности
  (`store.ClearLibrary`), не трогая пользователей и настройки.

## Статистика сканирования (дашборд)

- `scansvc.Result` содержит `StartedAt` и `Elapsed` (общая длительность обхода+импорта).
- После каждого запуска итог сохраняется в настройку `scan.last` (JSON `ScanSummary`):
  `started_at` (RFC3339, UTC), `elapsed_ms`, `found`, `created`, `updated`, `import_errors`.
- На дашборде (`/`) отображается блок «Последнее сканирование»:
  **Начало** (дата/время старта), **Продолжительность** (человекочитаемо: ч/мин/с)
  и краткая сводка `найдено · создано · обновлено [· ошибок]`.
- На `/scan` строка результата также содержит начало и длительность.

Время старта хранится в UTC; при отображении приводится к локальной зоне процесса.

## Коллекция из ZIP (пример развёртывания)

`docker-compose.go.yml` монтирует каталог коллекции read-only во внутренний путь
контейнера:

```yaml
volumes:
  - /run/media/ahtoh/SSD2/e-book:/books:ro
```

Сканер обходит `/books` рекурсивно и распаковывает ZIP-архивы с FB2 (`Zip: true`).
Путь добавляется в разделе «Каталоги сканирования» (`/settings`).
