# Почта (SMTP), проверка адресов и сброс пароля

Сервер исходящей почты портала `eopds-go`. Появилась в версии 0.52.0
(schema_version 8). Подсистема отвечает за:

- **настройку SMTP** в админке: сервер, порт, шифрование, вход, отправитель;
- **проверку соединения** и **тестовую отправку** (с проверкой адреса);
- **журнал отправок** (внутренняя таблица + операционные события);
- **сброс пароля по e-mail** для пользователей портала.

Пароль SMTP и токены сброса **никогда** не отдаются в интерфейс и не пишутся
в логи в открытом виде (журнал отправок пароль не содержит; токен хранится
только в виде SHA-256).

## Раздел «Почта (SMTP)»

Меню: **Настройки → Система → Почта (SMTP)** (`GET /settings?sec=mail`).
Раздел доступен **только администратору** (роль `admin` или root); модератор
и читатель его не видят (`settingsSectionAllowed` отсекает неизвестный раздел).

Страница состоит из блоков:

| Блок | Поля |
|------|------|
| Соединение | `host` (SMTP-сервер), `port`, `security` (`smtps` / `starttls` / `none`), `username`, `password` |
| Отправитель | `from_addr` (обязательно), `from_name`, `reply_to` |
| Отправка | чекбокс `enabled` — «Отправлять письма пользователям» |
| Проверка | «Проверить соединение» (`/settings/mail/verify`) |
| Тест | получатель `to` + «Отправить тестовое письмо» (`/settings/mail/test`) |
| Журнал | последние 50 записей (`/settings/mail/clear` — очистка) |

### Пароль

- Пустое поле = **не менять** текущий пароль.
- Значение `-` = **очистить** пароль.
- Пароль сохраняется как есть (SMTP-AUTH требует исходный секрет); в HTML
  выводится только признак «задан / не задан».

### Шифрование

| Режим | Порт по умолчанию | Что делает клиент |
|-------|-------------------|-------------------|
| `smtps` | 465 | неявный TLS с первого байта |
| `starttls` | 587 | обычное соединение → `STARTTLS` → TLS |
| `none` | 25 | без шифрования; **пароль запрещён** (локальный релей) |

Если режим `none` и задан пароль, сохранение отклоняется (`err=nocrypt`).

### Как выбирается механизм AUTH

Внутри TLS клиент выбирает механизм по предпочтению:
`SCRAM-SHA-256(-PLUS)` → `SCRAM-SHA-1(-PLUS)` → `NTLM` → `CRAM-MD5` →
`PLAIN` → `LOGIN`. Без TLS `PLAIN`/`LOGIN` **не используются** (передаются
только «-NOENC»-варианты, которые go-mail отклонит при отсутствии SSL).
Важно: Gmail/Яндекс/Mail.ru требуют TLS — используйте `smtps` или `starttls`.

### Проверка соединения

`POST /settings/mail/verify` подключается к серверу с настройками **из формы**
(не сохраняя их), проходит TLS и аутентификацию, затем `QUIT` — письмо не
отправляется. Результат (время и пояснение) записывается в настройки и виден
на странице.

### Тестовое письмо

`POST /settings/mail/test`:

1. проверяет, что настройки заполнены и включены (`err=incomplete` / `err=disabled`);
2. проверяет адрес получателя (синтаксис + DNS, см. ниже) — на невалидный
   адрес письмо **не** отправляется (`err=mail.check.*`);
3. ставит письмо в отправку (`flash=test_queued`), результат — в журнале.

Письмо уходит в отдельной горутине с таймаутом 30 с. Если процесс
перезапустить до завершения, запись останется в статусе `queued` — ретраев нет.

## Проверка адресов e-mail

Пакет `internal/emailcheck`: сначала синтаксис (`ValidSyntax`), затем DNS —
`MX` записи домена, при их отсутствии `A`/`AAAA`. Результат кэшируется
(по умолчанию 1 час) по домену и по адресу.

Статусы (`Result.Status`) и их ключи i18n:

| Статус | Значение | Ключ |
|--------|----------|------|
| `ok` | домен принимает почту | `mail.check.ok` |
| `syntax` | неверный формат | `mail.check.syntax` |
| `no_domain` | нет MX/A (письмо не доставится) | `mail.check.no_domain` |
| `dns_error` | временная ошибка DNS | `mail.check.dns_error` |
| `not_needed` | проверка не требуется | `mail.check.skipped` |
| `unknown` | не проверялся | `mail.check.unknown` |

Только `ok` считается «валидным» (`Result.Valid()`); `dns_error` —
запрет отправки до повторной проверки.

## Журнал отправок

Таблица `mail_sent` (`queued → sent | error`), отображаются последние 50
записей: время, получатель, тип письма (`test`, `password_reset`), статус и
текст ошибки. Очистка — `POST /settings/mail/clear`.

Дополнительно каждая отправка пишет операционное событие в «Сообщения системы»:

| Категория | Уровень | Когда |
|-----------|---------|-------|
| `mail.sent` | info | письмо отправлено |
| `mail.error` | warn | ошибка отправки |
| `mail.settings_saved` | info | сохранены настройки SMTP |
| `mail.verify_ok` / `mail.verify_failed` | info / warn | проверка соединения |
| `mail.password_reset_requested` | info | запрошен сброс пароля |
| `mail.password_reset_done` | warn | пароль изменён по ссылке |
| `mail.log_cleared` | warn | очищен журнал отправок |

Получатели в событиях и логах маскируются: `iv***@mail.ru`.

## Сброс пароля по почте

Доступен, когда почта настроена и включена (`MailReady`); иначе ссылка
«Забыли пароль?» на `/login` не показывается.

1. `GET /reset` — форма запроса адреса.
2. `POST /reset` — адрес проверяется (синтаксис + DNS); если адрес принадлежит
   активному пользователю, создаётся токен (TTL 1 час) и ставится письмо.
   **Ответ всегда одинаковый** (`302 → /reset?sent=1`), чтобы не раскрывать,
   какие адреса зарегистрированы. Предыдущие ссылки пользователя аннулируются.
3. `GET /reset/confirm?token=...` — форма нового пароля (минимум 8 символов).
4. `POST /reset/confirm` — пароль сохраняется (PBKDF2, как при регистрации),
   токен помечается использованным, **все сессии пользователя отзываются**,
   редирект на `/login?reset=1` с сообщением об успехе.

Токен одноразовый, хранится только хешем (`email_tokens.token_hash`),
просроченные и использованные удаляются (`PurgeEmailTokens`).

### Ограничение частоты

`POST /reset` защищён от генерации писем лимитами в памяти процесса:

| Ключ | Лимит | Окно |
|---|---|---|
| адрес e-mail | 3 запроса | 1 час |
| IP клиента | 10 запросов | 1 час |

- Лимит проверяется **до** DNS-проверки и постановки письма в очередь.
- При превышении ответ не меняется (`302 → /reset?sent=1`), письмо и токен
  не создаются, чтобы не раскрывать факт срабатывания лимита.
- В «Сообщения системы» пишется предупреждение `mail.reset_rate_limited`
  (`email` — замаскирован, `by_email`/`by_ip`, `retry_after` в секундах).
- IP берётся из `X-Forwarded-For` (последний адрес), затем `X-Real-IP`,
  затем `RemoteAddr` — см. `clientIP`.
- Счётчики хранятся в памяти и сбрасываются при рестарте; значения заданы
  в `resetPerEmailLimit/Window`, `resetPerIPLimit/Window` (`internal/admin/reset.go`).

### Базовый адрес ссылок

Ссылка в письме собирается как `<base>/reset/confirm?token=...`. `<base>` —
настройка `mail.public_url` (таблица `settings`), если задана; иначе — схема и
хост текущего запроса (`X-Forwarded-Proto: https` учитывается). За порталом с
обратным прокси на отдельном домене **задайте `mail.public_url`**.

## Хранилище

Миграция `0008_mail_smtp.sql` (PG и SQLite):

| Таблица | Назначение |
|---------|-----------|
| `mail_smtp` | одна строка (`id = 1`): параметры SMTP, отметка проверки, `updated_at`, `updated_by_id` |
| `mail_sent` | журнал отправок: `ts`, `recipient`, `subject`, `template`, `status`, `error`, `message_id`, `lang`, `user_id` |
| `email_tokens` | одноразовые токены: `user_id`, `email`, `kind` (`reset_password`, `verify_email`), `token_hash`, `ts`, `expires_at`, `used_at` (unix ms) |

Методы хранилища (`internal/store`): `GetMailSettings`, `SaveMailSettings`,
`AddMailSent`, `UpdateMailSent`, `ListMailSent`, `ClearMailSent`,
`CreateEmailToken`, `GetEmailToken`, `UseEmailToken`, `DeleteEmailTokens`,
`PurgeEmailTokens`, `GetUserByEmail`.

### Просроченные токены

Таблица `email_tokens` чистится **автоматически**: задача обслуживания
(`internal/admin/maintenance.go`) раз в час удаляет просроченные и уже
использованные токены, первый прогон — через 2 минуты после старта,
после подключения БД (см. `StartMaintenance` в `cmd/eopds/main.go`).

- `PurgeEmailTokens(ctx) (int64, error)` возвращает число удалённых строк;
- если что-то удалено, в «Сообщения системы» пишется событие
  `mail.tokens_purged` («обслуживание: удалено… — N»);
- пустой прогон событие не пишет — журнал не засоряется;
- ошибка задачи только логируется (`warn`), следующий прогон — через час.

Ручной вызов по-прежнему возможен (например, из тестов).

Письма в статусе `queued` при рестарте остаются как есть — это след
незавершённой отправки, а не ошибка.

| Тип/функция | Назначение |
|-------------|-----------|
| `Settings` | параметры SMTP; `Validate()`, `Configured()`, `Port` |
