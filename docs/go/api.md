# HTTP API Go-сервиса (`eopds serve`)

Базовый префикс API: `/api`. Все ответы API — JSON (`application/json`).
Аутентификация для admin-API — в разработке (см. roadmap); публичные
read-only эндпоинты доступны без неё.

## `GET /scan/status`

Статус фонового сканирования (опрос для плашки прогресса в разделе
`/settings?sec=scan`).
Требует авторизации (`eopds_session`). Ответ — всегда `200` JSON.

```json
{
  "running": true,
  "started_at": "2026-11-20T11:37:02Z",
  "found": 4502,
  "parsed": 4502,
  "created": 4502,
  "updated": 0,
  "errors": 0,
  "skipped": 0,
  "has_run": true
}
```

| Поле | Тип | Описание |
|---|---|---|
| `running` | bool | идёт ли скан прямо сейчас |
| `started_at` | string | старт текущего/последнего скана (RFC3339, UTC) |
| `finished_at` | string | завершение последнего скана (только после окончания) |
| `found` | int | найдено книг |
| `parsed` | int | успешно импортировано |
| `created` / `updated` | int | добавлено / обновлено |
| `errors` | int | ошибок импорта (парсинг + запись в БД) |
| `skipped` | int | файлов/архивов пропущено как неизменившиеся (инкрементальный скан) |
| `has_run` | bool | было ли хотя бы одно сканирование (с текущего запуска процесса) |
| `last_error` | string | текст ошибки запуска, если скан упал |

**Пример:** `GET /scan/status`

> Состояние хранится в памяти процесса (`scanState`). После перезапуска
> сервиса `running=false` до следующего запуска; итог прошлого скана доступен
> на дашборде (`scan.last` в настройках).

## `POST /scan/run`

Запуск сканирования в фоне (только admin). Сразу отвечает `303` на
`/settings?sec=scan#run`; прогресс опрашивается через `/scan/status`.

Параметры формы (application/x-www-form-urlencoded):

| Параметр | Значение | Описание |
|---|---|---|
| `full` | `1` | полный перескан: игнорировать отпечатки и перечитать все файлы |

Без `full` работает **инкрементальный скан**: файлы и ZIP-архивы, чьи
размер и `mtime` не изменились с прошлого прочитанного скана (таблица
`scan_files`), не парсятся повторно — они учитываются в `skipped`. Новые
и изменённые файлы обрабатываются как обычно. `FullRescan` (`full=1`)
полезен после ручной правки БД или если есть подозрение, что файлы
изменились в обход `mtime`.

Если скан уже идёт — запуск игнорируется (повторный `303`, статус `running=true`).

## `GET /api/health`

Состояние сервиса (алиас: `GET /healthz`).

```json
{
  "status": "ok",
  "version": "0.47.0",
  "commit": "abc1234",
  "built_at": "2026-01-16T10:00:00Z",
  "schema_version": 3,
  "db": "postgres"
}
```

`status`: `ok` | `degraded` | `error`.
`degraded` — например, несовпадение `schema_version`.

## `GET /api/version`

Версия и сведения о сборке.

```json
  "version": "0.47.0",
  "commit": "abc1234",
  "built_at": "2026-01-16T10:00:00Z",
  "go": "go1.23.4"
}
```

## `GET /library/suggest`

Подсказки живого поиска для веб-библиотеки (используется фронтендом строки поиска).

**Параметры запроса:**

| Параметр | Тип | Описание |
|---|---|---|
| `q` | string | строка поиска; короче 2 символов → пустой `items` |
| `by` | string | `title` (по названию, по умолчанию), `author` (по автору), `series` (по серии) |

**Коды ответов:** `200` — всегда (при ошибке БД — `500`).

**Пример:** `GET /library/suggest?q=анна&by=title`

```json
{"items":[
  {"id":11364,"title":"Анна Каренина","authors":["Лев Толстой"],
   "annotation":"«Анна Каренина» — …","format":"fb2"}
]}
```

Аннотация обрезается до 240 символов. Обложка — отдельным запросом
`/library/book/{id}/cover`.

## `GET /library/book/{id}/download`

Скачивание файла книги. **Требует авторизации** (гость → `303` на `/login`).
Ответ — файл (`Content-Disposition: attachment`), не JSON.

**Параметры:**

| Параметр | Тип | Описание |
|---|---|---|
| `id` | path | id книги |
| `fmt` | query | пусто/`<исходный>` — как есть; `fb2+zip` — ZIP «на лету»; прочие форматы (конвертация) → `404` |

**Коды ответов:**

| Код | Значение |
|---|---|
| 200 | файл отдан |
| 303 | гость → редирект на `/login` |
| 404 | книга не найдена, файл отсутствует или формат пока не поддерживается |

**Заголовки ответа:** `Content-Type` по формату (`application/x-fictionbook+xml`,
`application/epub+zip`, `application/zip`, …), `Content-Length` (если известен),
`Content-Disposition: attachment; filename*=UTF-8''<name>`.

**Побочный эффект:** для авторизованного пользователя книга добавляется на его
полку (`bookshelf`, обновляется `last_read_at`) и учитывается в популярности —
в `downloads` создаётся одна строка на пару (книга, пользователь); повторное
скачивание той же книги дубль не создаёт.

## `GET /api/forum/latest-topics`

Последние темы форума (кэш, таймаут 3с). Источник — `EOPDS_FORUM_SOURCE`.
Формат источника — [../forum.md](../forum.md).

```json
{
  "topics": [
    {
      "title": "Установка Easy OPDS через docker-compose",
      "url": "https://eopds.ru/topic/4/...",
      "category": "Техподдержка",
      "replies": 0,
      "last_post_at": "2026-01-12T08:30:00Z"
    }
  ]
}
```

При недоступности источника — `200` с пустым массивом или `503`
(поведение уточняется; UI скрывает блок при пустом ответе).
## `GET /dashboard/popular`
Страница «Популярные книги» (только для авторизованных). Список книг по
критерию популярности, постранично (по 60), с сортировкой. На дашборде
(`/dashboard`) тот же набор показывается кратко — по 3 книги в двух колонках
с заголовками-ссылками на эту страницу.

**Параметры запроса:**

| Параметр | Значения | По умолчанию | Смысл |
|---|---|---|---|
| `by` | `downloads` \| `rating` | `downloads` | критерий: популярность (уникальные читатели) / средняя оценка |
| `page` | ≥1 | `1` | страница |
| `sort` | `desc` \| `asc` | `desc` | направление (убывание/возрастание) |

**Поведение:**
- `by=downloads` — книги, которые хотя бы раз скачали или открыли в читалке;
  сортировка по числу **уникальных пользователей** (`COUNT(DISTINCT user_id)` +
  анонимные события). Повторы (скачал + прочитал, или несколько раз) не
  завышают популярность — одна строка на пару (книга, пользователь) в
  `downloads` (миграция 7);
- `by=rating` — книги, у которых есть хотя бы одна оценка (`book_ratings`),
  сортировка по средней оценке, затем по числу оценок.

> «Читать» (`GET /library/book/{id}/read`) тоже учитывается в популярности
> (`downloads.format='read'`), а OPDS-скачивание — через `/download`.

**Ответ:** HTML-страница со списком книг и пагинацией (как
[`/library/new`](library.md)). Прочие query-параметры сохраняются в ссылках
пагинации.

## `GET /dashboard/events/download`

Скачивание журнала сообщений системы (дашборд). Доступно только
**admin/root** и **moderator**; для остальных — `403`. Подробности, категории
событий и формат — [system-events.md](system-events.md).

**Параметры:** `lang` (query, необязательный) — язык строк (`ru`/`en`), по
умолчанию — язык интерфейса/сессии.

**Ответ:** `200` — `text/plain; charset=utf-8`, файл
`system-events-YYYYMMDD-HHMMSS.log`, одна строка на событие:
`2026-11-22 16:43:24 [инфо] администратор admin — скачал книгу «Маугли»`.
Строк — не больше `events.max_rows` (см. настройки).

**Коды ответов:** `200` — файл; `403` — недостаточно прав; `500` — ошибка БД.

## Коды ответов

| Код | Значение |
|---|---|
| 200 | OK |
| 503 | Источник временно недоступен (для внешних источников) |
| 500 | Внутренняя ошибка |
