## Переработка схемы БД (окно возможностей)

Пока проект переписывается на Go — **единственный момент**, когда можно свободно
изменить структуру таблиц. После стабилизации менять будет дорого.

Текущая схема (Go, `eopds-go/internal/store` + `docs/db-schema.md`): `books`,
`catalogs`, `authors`, `genres`, `series`, связи `book_authors`/`book_genres`/
`book_series`, `bookshelf`, `settings`, `eopds_meta`.

Что стоит продумать при переработке:
- [ ] **Именование** таблиц/колонок (сейчас смешение `snake_case` и префиксов;
      в Go — единый стиль, напр. `books`, `authors`, `book_authors`).
- [ ] **Индексы** под реальные запросы (поиск по `search_title`, `search_full_name`,
      сортировки, счётчики на дашборде).
- [ ] **Типы** (даты как `timestamptz`, размеры как `bigint`, булевы флаги вместо
      `integer` `avail`/`cat_type`).
- [ ] **Связи** (many-to-many через промежуточные таблицы — уже так; проверить
      каскады и внешние ключи под PostgreSQL и SQLite).
- [ ] **Counter** — пересмотреть: хранить кэш-счётчики или считать на лету
      (материализованные представления / триггеры).
- [ ] **Метаданные** (`eopds_meta`): `schema_version`, миграции, время установки.
- [ ] **Пользователи/доступ** (см. Issues #3): приглашения, роли, закладки.
- [ ] **Закладки/прогресс чтения** (см. Issues #2): таблица для позиции чтения.
- [ ] **Обложки** — таблица `book_covers` всегда в схеме; режим выбирает
      пользователь в админке (галочка с пояснениями): «извлекать онлайн»
      (по умолчанию, + HTTP-кеш) или «хранить на диске» (быстрее для больших
      библиотек). Внешние обложки от провайдеров хранятся всегда.
- [ ] **Кэш аннотаций** (см. Issues #1): где хранить внешние аннотации.

## OPDS-каталог (приоритет)

Отдача библиотеки по протоколу OPDS — ядро проекта. Один набор данных,
две тонкие сериализации:

- [x] **OPDS 1.2 (Atom)** — `application/atom+xml;profile=opds-catalog;kind=...`.
      Поддерживают все читалки (Moon+, FBReader, KOReader, Aldiko).
      См. [go/opds.md](go/opds.md).
- [x] **OPDS 2.0 (JSON)** — `application/opds+json` (Readium-совместимые клиенты).
- [x] **Согласование формата** по `Accept`/`?format=` (1.2 — по умолчанию;
      `application/opds+json`/`?format=json` → 2.0). Один набор данных, две сериализации.
- [x] Корневой navigation feed: Новые / Все книги / Авторы / Серии / Жанры + Поиск.
- [x] Acquisition feeds: книги с `rel="http://opds-spec.org/acquisition"`,
      ссылки на скачивание (`?fmt=`), обложки (image/thumbnail).
- [x] Поиск (`opensearch`), пагинация, обложки (`rel=.../image`), MIME-типы.

## Конвертеры форматов (на скачивание)

- [x] **EPUB 3** — конвертер из `internal/fb2render` (XHTML + OPF + NAV + ZIP).
      `?fmt=epub|epub3` в download, acquisition-ссылка в OPDS. См. [go/epub.md](go/epub.md).
- [x] **EPUB 2** — тот же контейнер, `version="2.0"` в OPF + NCX. Флаг `?fmt=epub2`.
- [~] **Kobo EPUB (kepub)** — отдаётся EPUB3-контейнер с расширением `.kepub.epub`
      (`?fmt=kepub`). `koboSpan`-разметка (пагинация Kobo) — ещё не сделана.
- [ ] **TXT / Markdown (md)** — тривиально из отрендеренного HTML; опционально (позже).
- [x] **AZW8 / KFX / PDF — НЕ делаем.** KFX — закрытый формат Amazon
      (технически/легально воспроизвести нельзя), AZW8/KF8 — тяжёлый и нишевый,
      PDF из переформатируемого FB2 даёт плохой результат. Отдавать `404`
      (конвертер не подключён). Книги в этих форматах — скачивание исходника.

## Самообновление (in-place self-update) — обязательный пункт первого релиза

> Не срочно, но **должно войти в первый релиз**. Реализовать по аналогии с
> архитектурой [0xJacky/nginx-ui](https://github.com/0xJacky/nginx-ui): приложение
> обновляет само себя через веб-интерфейс как на хосте (systemd), так и в Docker.

### 1. Единый бинарник и версионирование
- [ ] Убедиться, что фронтенд встраивается в Go-бинарник через `go:embed`
      (если ещё нет — настроить). Учесть: сейчас шаблоны/статика (`internal/admin/templates`,
      `internal/admin/static`) читаются через embed — проверить полный набор.
- [ ] Глобальная переменная `Version` (по умолчанию `"dev"`), подставляется при сборке
      через `-ldflags "-X main.version=..."` (уже есть `internal/version` + VERSION — свериться).
- [ ] Все пользовательские данные (конфиги, БД, логи, кэш обложек) — в отдельной
      директории данных (`--data-dir` / `DATA_DIR`), изолированно от пути к бинарнику.

### 2. Бэкенд-модуль обновления (`internal/updater`)
- [ ] Библиотека self-update с поддержкой проверки контрольных сумм **SHA-256**
      (например, `github.com/minio/selfupdate` / `creativeprojects/go-selfupdate` —
      выбрать актуальную; в промте библиотека указана опечаткой `://github.com`).
- [ ] Проверка последнего релиза на GitHub (`owner/repo` из `git remote`/`go.mod`)
      и сравнение с текущей версией (SemVer).
- [ ] Атомарная загрузка и подмена текущего бинарника (`os.Executable()`).
- [ ] Корректное завершение процесса (`os.Exit(0)`) с задержкой ~500 мс–1 с
      после финального статуса клиенту — чтобы супервизор (systemd/Docker) перезапустил.
- [ ] Защита от конкурентного запуска обновлений (`sync.Mutex` / `atomic.Bool`).

### 3. API и стриминг прогресса
- [ ] Эндпоинт проверки обновлений: текущая версия, последняя, `has_update`, release notes.
- [ ] Эндпоинт запуска обновления с потоковым прогрессом (SSE или WebSocket — что
      органичнее для текущего stdlib-роутера): этапы `checking`, `downloading`,
      `verifying`, `replacing`, `restarting`, `error`.
- [ ] Лёгкий `/api/health` (статус + текущая `Version`) — уже есть `/api/health`,
      дополнить полем версии/статуса при необходимости.

### 4. Frontend (Web UI)
- [ ] Блок управления обновлениями (в настройках / у версии в шапке-футере):
      текущая версия и кнопка «Проверить обновления».
- [ ] Модальное окно/панель с changelog и кнопкой «Обновить сейчас».
- [ ] Отображение прогресса этапов.
- [ ] После `restarting`/обрыва соединения — поллинг `/api/health` каждые 1.5 с;
      при ответе с новой версией — уведомление об успехе и перезагрузка страницы.

### 5. Инфраструктура релизов и деплоя
- [ ] `.goreleaser.yaml` (v2): кросс-компиляция `linux/amd64`, `linux/arm64`,
      `darwin/amd64`, `darwin/arm64`, `windows/amd64`; `checksums.txt`; `Version` через `ldflags`.
- [ ] GitHub Actions `.github/workflows/release.yml`: по тегу `v*` сначала собрать

## Далёкое будущее — идеи из audiobookshelf

Приоритет: **самый низкий** (сначала — ядро Go, схема, сканер, веб, админка).
Источник вдохновения: [audiobookshelf](https://github.com/advplyr/audiobookshelf)
(`server/providers/`). Реализовывать **только после** базовой функциональности.

- [ ] **Провайдеры метаданных/обложек (поиск и подтягивание).**
      Плагинная архитектура: интерфейс `Provider` (`Search`, `FetchMetadata`,
      `FetchCover`), набор реализаций, выбор вручную или авто:
      OpenLibrary, Google Books, iTunes, **FantLab** (российская фантастика —
      идеально для аудитории eopds), MusicBrainz и др. + кастомный адаптер.
- [ ] **Поиск обложек** для книг без обложки: запрос к провайдерам, выбор
      пользователем, сохранение (через `book_covers`; здесь хранение обязательно —
      нельзя дёргать чужой API на каждый показ).
- [ ] **Поиск/заполнение аннотаций** из провайдеров (Issues #1) → `annotations_cache`.
- [ ] **Парсинг метаданных из файлов** (EPUB/MOBI/PDF, помимо FB2): авторы, серия,
      язык, ISBN, год, обложка (частично уже в Go-сканере, расширить).
- [ ] **Встраивание метаданных и обложки обратно в файл** (как «Embed metadata»
      в audiobookshelf) — опционально, с осторожностью.
- [ ] **Автоопределение изменений библиотеки** (file watcher) вместо ручного
      пересканирования: инкрементальные обновления по mtime (см. сканирование).
- [ ] **Дубликаты/качество метаданных**: обнаружение дублей, «обогащение»
      описаний, объединение авторов с разным написанием.
- [ ] **Читалка/просмотрщик EPUB-PDF** (перекликается с Issues #2): прогресс,
      закладки, синхронизация между устройствами (уже заложено в `bookshelf`).

> При заимствовании идей — переосмыслить под Go + нашу схему БД; код
> audiobookshelf (Node/Sequelize) напрямую не переносим.
